# 0005 – Push

- **Status:** Accepted
- **Datum:** 2026-10-02

## Kontext

Geräte sollen zeitnah von Änderungen erfahren, ohne dass Datenintegrität von Push abhängt. Siehe [Push-Strategie](../architecture/push.md).

## Entscheidung

Der Vorschlag wird unverändert angenommen:

- Web Push (VAPID) direkt vom self-hosted Server; Keypair wird vom Server erzeugt und gespeichert.
- Subscription nur nach direkter Nutzeraktion.
- Payload ohne Inhalte: `sync_available`, Workspace-/Installationsreferenz, optional Badge.
- Optionales Hosted Push Relay als Paid-Feature (Phase 9).

## Konsequenzen

- Das `backend` erzeugt das VAPID-Keypair beim ersten Start und speichert es persistent (Teil des Backups).
- Subscriptions werden pro Gerät gespeichert und bei `410 Gone` vom Push-Dienst entfernt.
- Sync darf nie von Push abhängen (Start-, Fokus- und Timer-Sync bleiben Pflicht, siehe [ADR 0002](0002-sync-protocol.md)).
- Testfälle: T-OFF-06, T-PWA-02, T-PWA-03.
